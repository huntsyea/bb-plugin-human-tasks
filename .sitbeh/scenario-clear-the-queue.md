# Clear the queue

**Situation:** builder returns later with a batch of tasks from several agents.

**Limitations:** within a short session; sometimes on a phone; some tasks can't
be done yet (DNS propagation, office hours, waiting on someone else).

**Actions:** scan what's waiting and what's urgent → batch similar ones → do,
defer, or drop each → confirm each agent resumed.

**Thinking:** "Which of these actually block something?" · "This one can only
happen tomorrow" · "Half of these are stale" · "I don't want to open each one."

**Feelings:** overwhelmed by a long list, guilty about stale items.

| Action | Barrier | Reason | Mechanism |
| --- | --- | --- | --- |
| Scan | Can't | Everything looks equal | Blocking group first; M9 due dates ("due in 9d"); stats strip |
| Batch | Can't | Mixed projects, bots, kinds | Filters always visible (project, bot, kind) |
| Act | Don't want | Opening each task is slow | M11 quick actions on collapsed rows (done, open site, hand off, menu) |
| Defer | Can't | Not doable yet | M12 snooze (1h, tomorrow, next week) and agent-set "not before"; resurfaces with a toast |
| Drop | Don't know | Thread that asked is gone | M13 "The thread that asked is archived — still needed?" with quick dismiss |
| Confirm | Don't know | No feedback per task | M7 "Agent resumed" per task |

**Reinforce:** "All caught up" state; finished tab shows who resumed.
Dropped → snoozed tasks come back on time; due dates turn red.
